# 🔐 Политика безопасности

## Поддерживаемые версии

Пока проект находится на стадии `0.x`, исправления безопасности выпускаются для последней опубликованной версии и ветки `main`.

## Как сообщить об уязвимости

Не публикуйте уязвимость в открытом Issue, если она может привести к:

- выполнению команд;
- обходу ограничений импорта;
- ZIP Slip или path traversal;
- SQL/HTML-инъекции;
- раскрытию секретных значений;
- записи за пределы каталога данных;
- повреждению или подмене снимков.

Используйте GitHub Security Advisories репозитория. В отчёте укажите версию, шаги воспроизведения, влияние и безопасный минимальный пример.

## Защитные принципы

- данные из реестра, служб и задач никогда не выполняются как команды;
- SQL-запросы параметризованы;
- HTML-значения экранируются;
- секретные значения маскируются;
- приложение не выполняет автоматический rollback;
- повышение прав требует явного решения пользователя;
- внешние снимки не должны считаться доверенными.
