# SysDiff 0.11.0 — Legacy Bridge

Релиз добавляет реальный upgrade chain от переносимых форматов SysDiff 0.3–0.9 к стабильному public Schema Contract v1.

## Главное

- `sysdiff legacy matrix|status|plan|verify|convert`;
- aliases `upgrade` и `bridge`;
- read-only dry-run plan;
- conversion только после `--yes`;
- automatic side-by-side backup;
- atomic output и post-conversion verification;
- source/output SHA-256 audit;
- handler legacy comparison reports;
- handler legacy investigation bundles;
- checksum rebuild для каждого bundle payload;
- byte-for-byte preservation вложенных `.sdshot`;
- idempotent no-op для current v1 files.

## Поддерживаемые migrations

### Comparison report 0.3–0.9

Legacy JSON без `format`, `formatVersion` и `sysDiffVersion` получает metadata Schema Contract v1. Исходный comparison payload и unknown additive fields сохраняются.

Так как старые reports не записывали producer version, migration использует честный SemVer sentinel:

```text
0.0.0-legacy
```

### Investigation bundle 0.3–0.9

- `manifest.json` получает `schemaVersion: 1`;
- `report.json` преобразуется в comparison contract v1;
- `.sdshot`, Markdown, HTML и другие payload entries сохраняются;
- `checksums.sha256` пересчитывается;
- output ZIP повторно проверяется целиком.

## Безопасность

- future schema не downgrades;
- unknown legacy shape не repair-ится автоматически;
- каждый ZIP path проверяется;
- duplicate entries отклоняются;
- исходные checksums проверяются до backup/conversion;
- backup создаётся до первой записи;
- output создаётся через temporary file и atomic move;
- при failed post-validation output удаляется, а in-place source восстанавливается;
- преобразованный файл не импортируется автоматически.

## Тестирование

Integration tests покрывают:

- legacy comparison plan;
- backup byte equality;
- preservation unknown fields;
- current-file no-op;
- future schema rejection;
- legacy bundle conversion;
- byte equality вложенных snapshots;
- checksum rebuild;
- tampered checksum rejection до backup.

Release smoke выполняет полный comparison flow через опубликованный `sysdiff.exe`: plan → convert → backup check → verify.

## Совместимость

- public schema остаётся `1`;
- `.sdshot` format/schema остаются `1`;
- SQLite `user_version` остаётся `9`;
- Schema Contract minimum reader остаётся `0.10.0`;
- current writer version становится `0.11.0`;
- старые CLI-команды делегируются через `V11 → V10 → V9 → V8 → V7 → V6 → V4 → V3`.
