# SysDiff 0.9.0 — Migration Lab

Релиз добавляет безопасный механизм изменения локальной SQLite-базы перед переходом проекта к стабильной публичной schema 1.0.

## Главное

- `sysdiff migration status|plan|history|apply`;
- dry-run plan без изменения пользовательских данных;
- `migration apply` только после явного `--yes`;
- SQLite-consistent backup перед миграцией существующей базы;
- exclusive migration lock;
- транзакционный rollback при ошибке SQL;
- итоговый `PRAGMA quick_check`;
- восстановление backup при нарушении целостности после commit;
- guard от базы с более новым `PRAGMA user_version`;
- машинный JSON-вывод со строковыми enum statuses.

## Миграция 0.9

`0.9.0-migration-lab` является additive migration и добавляет:

- `migration_runs` для истории успешных и неуспешных запусков;
- `database_metadata` для внутренних metadata keys;
- индекс истории `app_migrations`;
- индекс migration runs;
- `PRAGMA user_version = 9`.

Основные snapshot/comparison/investigation tables не переписываются.

## Новая и существующая база

Новая пустая база автоматически получает текущий ledger без создания бессмысленного backup.

Существующая база не изменяется при обычном запуске. Пользователь сначала запускает:

```powershell
sysdiff migration plan
```

и затем явно подтверждает:

```powershell
sysdiff migration apply --yes
```

## Безопасность

- backup создаётся до первого migration SQL;
- WAL сбрасывается checkpoint перед backup;
- backup проверяется через `quick_check`;
- migration SQL и history records находятся в одной transaction;
- неизвестные migration IDs блокируют применение;
- более новый `user_version` отклоняется до store initialization;
- параллельный migration process блокируется lock-файлом;
- пользовательские строки из базы не выполняются как SQL или команды.

## Тестирование

Добавлены integration tests:

- backup сохраняет существующий snapshot;
- migration применяется один раз;
- повторный apply является безопасным no-op;
- bootstrap новой базы не создаёт backup;
- injected SQL failure откатывает созданную таблицу и history row;
- future `user_version` отклоняется.

Release smoke проверяет:

- ProductVersion `0.9.0`;
- Migration Lab help;
- current migration status;
- migration history;
- Compatibility Center;
- updater, doctor, timeline и Case Vault;
- Cyber Console Migration Lab frame.

## Совместимость

- `.sdshot` format/schema остаются `1`;
- SQLite snapshot/comparison schema не меняется;
- investigation tables 0.6 остаются совместимыми;
- stable public schema 1.0 пока не объявляется;
- старые CLI-команды делегируются через `V9 → V8 → V7 → V6 → V4 → V3`.
